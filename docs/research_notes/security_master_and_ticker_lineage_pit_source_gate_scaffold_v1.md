# Project Underdog - Security Master and Ticker Lineage PIT Source Gate Scaffold v1

## SECTION 1 - Scaffold Overview

This note documents the research-only source-gate scaffold for point-in-time security identity and ticker lineage.

Classification: `SOURCE_GATE_SCAFFOLD_READY_WITH_EXTERNAL_DEPENDENCIES`.

The scaffold establishes governance templates, controlled vocabularies, dry-run source scoring, runner modes, and focused tests. It does not ingest external data, connect to CRSP, create databases, build PIT tables, build lineage, reconstruct economic classifications, reconstruct peer groups, generate panels, compute IC, run validation, mutate governance thresholds, register production outputs, or introduce ML.

Implemented runner:

- `pipelines/run_crsp_security_master_ticker_lineage_pit_v1.py`

Added source-gate modes:

- `--list-source-gates`
- `--validate-source-gates`
- `--dry-run-source-gates`

## SECTION 2 - Manifest Schema

The source-gate manifest schema is represented by:

- `pit_source_gate_manifest_schema.csv`
- `pit_source_gate_manifest_template.csv`

Required manifest fields:

- `source_id`
- `provider`
- `source_name`
- `source_type`
- `source_version`
- `coverage_start`
- `coverage_end`
- `coverage_ratio`
- `effective_date_support`
- `licensing_status`
- `pit_capability`
- `lineage_capability`
- `reproducibility_status`
- `validation_status`
- `approval_status`
- `approval_outcome`
- `notes`

The manifest schema is intentionally source-agnostic. It represents candidate source evidence but does not authorize source loading.

## SECTION 3 - Vocabulary Definitions

Controlled vocabularies are emitted to:

- `pit_source_gate_controlled_vocabularies.csv`
- `pit_source_gate_controlled_vocabularies.json`

Vocabulary groups:

- `source_status`
- `source_type`
- `pit_readiness`
- `lineage_readiness`
- `licensing`
- `validation_status`
- `approval_outcome`
- `effective_date_support`
- `reproducibility_status`

Blocking values include:

- `static_snapshot_only`
- `ticker_only`
- `current_snapshot_only`
- `none`
- `license_review_required`
- `redistribution_blocked`
- `unknown`
- `blocked`
- `manual_notes_only`
- `unresolved`

The scaffold fails closed when manifest values are missing, invalid, static-only, ticker-only, unreproducible, or licensing-unreviewed.

## SECTION 4 - Source-Gate Logic

The dry-run evaluator scores source candidates across:

- PIT capability
- lineage capability
- effective-date support
- licensing status
- reproducibility status
- coverage ratio

Dry-run outputs:

- `pit_source_gate_dry_run_candidates.csv`
- `pit_source_gate_dry_run_report.csv`
- `pit_source_gate_scaffold_manifest.json`

The dry-run examples are synthetic placeholders. They prove scoring behavior without accessing external data.

Fail-closed behavior:

- Static current profile snapshots are blocked.
- Ticker-only sources are blocked.
- Sources without reviewed licensing are blocked.
- Sources without effective dates or date-stamped snapshots are blocked.
- Invalid vocabulary values are rejected.
- Passing a dry-run source gate authorizes only future implementation review, not ingestion or lineage construction.

## SECTION 5 - Approval Workflow

Allowed workflow:

1. List controlled vocabularies and manifest requirements.
2. Validate source-gate templates and vocabularies.
3. Dry-run synthetic source-gate examples.
4. In a later task, evaluate real source manifests without ingestion.
5. Only after source acceptance, request a separate lineage implementation task.

Approval outcomes:

- `approved_for_source_gate_only`
- `approved_for_pit_implementation`
- `conditional_approval`
- `manual_review_required`
- `diagnostic_only`
- `rejected`

Current scaffold approval:

- Source-gate scaffold is ready.
- External source acceptance remains unresolved.
- Metadata ingestion and lineage construction remain blocked.
