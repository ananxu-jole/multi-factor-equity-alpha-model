### Sector / industry coverage
- Sector distribution is now broad enough for descriptive diagnostics.
- All 11 major sectors have meaningful representation.
- Sector-level diagnostics are allowed for coverage, exposure, and concentration review.
- Industry/peer group coverage is improved but still limited.
- Many peer groups remain thin below the 8-name threshold.

### Peer group methodology
- The chosen methodology is industry-first peer group assignment with sector fallback.
- Peer groups are manual/static labels, not yet validated as point-in-time.
- Minimum useful peer-group size is treated as 8 tickers.
- Thin-group warnings are required for smaller groups.
- No peer-relative transforms or peer-conditioned alpha research are allowed until point-in-time metadata is available.
- Current peer-group diagnostics are descriptive only, not validation-quality.

### Diagnostic fields
- Recommended fields include:
  - ticker, company_name, sector, industry, subindustry, peer_group_label, classification_system, source, source_version, as_of_date, effective_start, effective_end, collection_timestamp, universe_version, metadata_version, snapshot_warning, point_in_time_quality.
- Size/market-cap fields are useful for descriptive controls but are blocked for validation without point-in-time integrity.
- Behavioral bucket fields such as liquidity_bucket, volatility_bucket, turnover_bucket, and beta_bucket are useful controls and diagnostics but not substitutes for economic metadata.

### Current readiness assessment
- Ready for descriptive coverage, peer-group thinness, sector distribution, and inventory exposure auditing.
- Blocked for alpha validation, sector-relative or peer-relative scoring, portfolio construction, ML conditioning, and production metadata ingestion.
- The metadata layer remains a static snapshot; point-in-time source lineage and effective-date control are required before moving beyond diagnostics.

## SECTION 6: ML Readiness Assessment

### Data readiness
- Raw OHLCV panels and candidate signal panels exist and are usable for research.
- Metadata is now more complete but remains static snapshot only.
- Point-in-time economic metadata is not yet available, so ML models should not be conditioned on sector/peer features in validation or production.
- Data readiness is moderate for raw signals and low for economic context-aware modeling.

### Feature readiness
- Candidate features are available, but the strongest current features are still in active research and not frozen for production.
- Conditional activation/repair features are promising, but the current inventory is not stable enough for ML training.
- Economic-context features are not yet ready for robust use because peer-group and size features lack point-in-time validation.

### Label readiness
- Raw h10/h20 forward-return IC remains the validation anchor and is the strongest label foundation.
- Recovery-quality targets have been tested diagnostically but are not approved as label substitutes.
- Label readiness is acceptable for research diagnostics but not for broad ML training or production labeling.

### Conditional alpha readiness
- Conditional alpha remains research-only.
- The conditional-alpha path has not been wired into production.
- ML introduction is not recommended until the conditional inventory is stabilized, watch-monitor risks are resolved, and guardrails are formalized.

### Recommended ML timing
- Do not introduce ML now.
- Wait until: (a) the Track B fixed candidate package is rebuilt and equivalence-tested, (b) the conditional inventory has stable monitoring refreshes, and (c) point-in-time economic metadata is available for feature conditioning.
- When ready, introduce ML as a later research layer rather than as a primary discovery mechanism.
