## Executive Overview

Phase 5 exists because Project Underdog has reached the point where the highest-value scientific uncertainty is no longer "can we discover another OHLCV transformation?" but "can we add authoritative, point-in-time external information without breaking the project's scientific discipline?"

The OHLCV-first era answered several core questions. Directly measurable OHLCV state-transition mechanisms can produce useful evidence. Hostile/stress repair, participation/breadth repair, persistence/rank structure, and volatility-of-volatility contain real signal candidates. At the same time, broad abstract OHLCV mechanisms such as event topology, dispersion path narratives, and non-hostile leadership rotation have produced weak or negative evidence under frozen horizons.

Phase 5 is motivated by the largest remaining independent information gap: authoritative PIT metadata and economic context. Peer-relative research could test whether repair, stabilization, persistence, rank behavior, liquidity recovery, volatility normalization, and deterioration are idiosyncratic or simply broad sector/industry/size effects. That question cannot be answered safely with static metadata, current ticker labels, or unlicensed assumptions.

Relationship to previous phases:

- Earlier phases built OHLCV discovery discipline, validation discipline, and governance discipline.
- Platform v2 added hypothesis-first science, orthogonality, falsification, bounded refinement, and negative-evidence preservation.
- Phase 5 extends those principles from internal OHLCV evidence to external information evidence.

Relationship to future ML:

- Phase 5 does not introduce ML.
- It creates the evidence and metadata substrate that may later make ML scientifically defensible.
- ML remains deferred until family diversity, PIT metadata, feature lineage, label discipline, and model-governance requirements are stronger.

Major expected outcomes:

- Evidence-backed source authority decisions.
- Accepted or rejected PIT metadata paths.
- Clear source-gate outcomes for security identity, ticker lineage, company-security linkage, economic classifications, and peer construction.
- A reproducible external-information foundation for future peer-relative alpha research.
- Preserved Platform v2 discipline as the project expands beyond OHLCV.

## Scientific Philosophy

Phase 5 is information expansion rather than feature expansion.

The project should not treat external sources as a way to create more features faster. It should treat them as new evidence channels that must earn scientific authority. A sector label, ticker mapping, company identifier, delisting flag, peer group, market-cap bucket, or corporate-event record is not automatically usable because it exists. It becomes usable only if its source, license, entitlement, date semantics, lineage, retention rights, reproducibility path, and governance status support the scientific claim being made.

Guiding principles:

- Authoritative evidence before authority: no source role is granted from public descriptions, convenience, or assumptions.
- PIT first: historical identity, classification, links, and peer membership must be known-date safe.
- Contamination avoidance: external metadata must reduce false interpretation, not introduce look-ahead, survivorship, ticker-reuse, or static-label contamination.
- Reproducibility: source snapshots, documentation references, row counts, checksums or controlled references, and reviewer decisions must support later audit.
- Falsification: Phase 5 must be able to conclude that a source, taxonomy, peer construction, or frontier is not usable.
- Negative-evidence preservation: rejected sources, insufficient entitlements, failed date semantics, and unusable classifications are permanent scientific evidence.
- Bounded refinement: external information work should proceed in small source-role and hypothesis units, not broad metadata ingestion.
- Modular research: security identity, ticker lineage, company linkage, classification history, peer construction, and peer-relative modules are separate lifecycle objects.
- Incremental information gain: each external-information family must prove information beyond existing OHLCV families and contamination references.
- Independent validation: future peer-relative claims require validation separate from source acceptance.

Phase 5 does not redefine Platform v2. It extends Platform v2 by adding an external-information authority layer before any formula or module work can rely on non-OHLCV evidence.

## Success Criteria

Phase 5 scientific success should be judged by evidence quality, not implementation volume.

Success criteria:

- At least one authoritative PIT source path is accepted or explicitly rejected with documented evidence.
- Security identity and ticker-lineage authority requirements are resolved enough to decide whether field-level mapping may begin.
- License, entitlement, retention, archive, checksum/control-reference, documentation, and publication-rights evidence are captured or documented as blockers.
- Peer-relative hypotheses are narrowed into source-dependent, falsifiable scientific questions without formulas.
- Static metadata remains blocked from validation-quality use.
- Contamination controls are strengthened for peer-relative/economic-context claims.
- Negative source findings and rejected source roles are preserved.
- Reproducibility standards remain intact under external-license constraints.
- Governance remains fail-closed and no source becomes authoritative by convenience.

No numerical thresholds are defined by this program note.

## Relationship To Machine Learning

ML remains deferred.

Why ML is deferred:

- Current family diversity is still too concentrated in hostile/stress repair, persistence/rank satellites, and VoV candidate-level evidence.
- PIT peer/economic features are not accepted.
- Static metadata would create look-ahead and false peer controls.
- The project has candidate-level validation infrastructure, not full ML feature-store/model-governance infrastructure.

What Phase 5 should generate for future ML:

- Authoritative feature lineage.
- PIT-safe identity, classification, peer, and size context.
- Evidence of independent information beyond OHLCV families.
- Stronger contamination references.
- Source-aware reproducibility and audit trails.
- Negative evidence about unusable sources and metadata families.

Conditions that would later justify ML:

- Multiple validated independent families, including at least one accepted external-information family.
- Accepted PIT metadata with reproducible lineage.
- Stable labels and validation protocols for model experiments.
- Explicit ML governance, leakage controls, and interpretability requirements.
- Evidence that manual hypothesis-driven research has produced enough orthogonal features for a model to learn structure rather than state concentration.

Risks that would remain after Phase 5:

- ML could still overfit source-specific artifacts.
- External information may create subtle availability-lag leakage.
- Model complexity could obscure scientific mechanisms.
- Portfolio objectives could pressure the project to weaken research standards.

Phase 5 should make ML more scientifically plausible later; it should not introduce ML now.

## Phase Boundaries

### What Completes Phase 5?

Phase 5 is complete when the project can make evidence-backed decisions about whether authoritative external information is scientifically usable. Completion may be positive or negative.

Completion states may include:

- accepted source-gate readiness for field-level mapping;
- explicit rejection or parking of source families due to license, entitlement, retention, coverage, date semantics, or reproducibility constraints;
- documented source-role authority decisions;
- approved roadmap to peer-relative module design after accepted PIT metadata;
- or formal conclusion that external-information integration remains blocked.

### What Begins Phase 6?

Phase 6 begins only after Phase 5 produces accepted external-information evidence sufficient to support a new scientific layer. Possible Phase 6 themes:

- peer-relative alpha module design using accepted PIT metadata;
- external-information feature inventory;
- ML readiness design after validated external-information families exist;
- or portfolio-research preparation after multiple independent families mature.

## Open Scientific Questions

### High Confidence

- OHLCV-only broad abstract discovery has lower marginal return than earlier in the project.
- Peer-relative/economic context is the largest independent scientific gap.
- Static metadata is not validation-quality.
- External source work must remain fail-closed until evidence exists.

### Moderate Confidence

- PIT peer context could distinguish idiosyncratic repair from broad recovery.
- Industry/sector/size context could clarify rank, persistence, volatility, and liquidity mechanisms.
- VoV will remain useful as a contamination reference and possible active research family, pending contamination review.

### High Uncertainty

- Whether institutional/license paths provide usable CRSP/Compustat/CCM or equivalent data.
- Whether official documentation supports known-date and publication-date semantics.
- Whether retention and derived-data rights allow reproducible research.
- Whether peer-relative features will add positive IC after all controls.

### Unknown

- Which source family will be accepted, if any.
- Which classification taxonomy will be scientifically adequate.
- Whether peer groups will have enough historical coverage.
- Whether future ML will add value after Phase 5.

## Recommended Immediate Priorities

1. Complete user-led institutional access and entitlement outreach using the prepared inquiry package.
2. Capture license, entitlement, retention, archive, checksum/control-reference, and publication-rights evidence in controlled form.
3. Resolve source-role requirements for security identity, ticker lineage, company-security linkage, classification history, and known-date authority.
4. Continue source-independent PIT acceptance-test design for fail-closed identity, ticker, classification, and peer-membership semantics.
5. Preserve static/manual metadata as diagnostic-only and prevent promotion into alpha use.
6. Keep VoV contamination-review follow-through as an OHLCV inventory hygiene task, not as the main strategic phase.
7. Defer implementation, field mapping, source access, peer construction, formulas, panels, IC, validation, production, and ML until evidence gates authorize later lifecycle steps.

These priorities are evidence and design oriented. They do not recommend implementation.
