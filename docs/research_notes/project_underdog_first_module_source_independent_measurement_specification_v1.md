## 2. Measurement Philosophy

Source-independent measurement describes the scientific observations Project Underdog must eventually be able to make before any calculation method, source binding, field mapping, or implementation design is chosen.

This note therefore defines:

- what phenomenon must be observable;
- what each observation means scientifically;
- what information role each observation serves;
- what temporal relationships must be preserved;
- what context must be present for interpretation;
- what the observation must exclude to remain scientifically bounded.

It does not define how observations are calculated. It does not define source fields, database schemas, equations, estimators, transforms, thresholds, ranking rules, weights, peer-construction procedures, code paths, validation tests, or production behavior.

The core discipline is simple: measurement meaning must be stable before formulas appear. Future formula work may translate these observations into specific procedures, but it must not change the scientific claim.

## 3. Primary Scientific Observation

Primary scientific observation:

Project Underdog seeks to observe whether, after a pre-defined stress context, the apparent repair of a target security can be interpreted as repair common to historically valid economic comparators, repair specific to the target security, or an unresolved mixture of both.

This observation has three essential parts:

- an observed post-stress repair state for the target security;
- an observed post-stress repair state for the valid comparator context;
- an interpretive decomposition of the target observation into common-versus-security-specific meaning.

The observation does not assert predictive value. It asks whether peer/economic context changes the interpretation of an existing repair-family observation.

## 6. Observation Timing

The measurement specification requires temporal relationships, not numeric horizons.

Required timing relationships:

- The post-stress context must be established before the repair interpretation is made.
- Own-security repair must be observed after the stress context to which it refers.
- Peer-common repair must refer to the same historical comparison relationship as the target observation.
- Comparator context must be valid for the historical time being interpreted, not assigned using current or future knowledge.
- Market context and existing repair-family anchors must align with the same historical observation relationship.
- Source authority, identity, lineage, classification, and availability evidence must be knowable as of the relevant project-known relationship before empirical use is ever permitted.
- A future forecast relationship, if later defined, must occur after the observation and interpretation relationship. This note does not define that relationship.

Conceptual timing terms:

| Timing concept | Measurement meaning |
|---|---|
| Observation window | The relationship in which own repair and comparator repair are observed after stress. |
| Contextual window | The relationship in which economic and market context are valid for interpretation. |
| Comparator window | The relationship in which comparator behavior is historically comparable to the target. |
| Forecast relationship | A later lifecycle concept used only if formula and validation work are separately authorized. |
| Temporal ordering | Authority, identity, context, stress, repair, comparator behavior, decomposition interpretation, and future evaluation must not be reordered by hindsight. |

No numeric horizons are introduced.

## 7. Comparator Specification

The comparator exists to answer one scientific question:

Was the target security's observed post-stress repair common among historically valid economic comparators, or did it contain security-specific meaning?

The comparator is not the hypothesis itself. It is the contextual observation needed to interpret the target observation.

The comparator must remain:

- source-independent;
- historically valid;
- identity-safe;
- context-valid;
- temporally safe;
- reproducible;
- explicitly bounded to the first-module question.

The comparator must not become:

- peer construction;
- a source-selection exercise;
- a taxonomy-selection exercise;
- a current-state industry label;
- a fallback hierarchy;
- a ranking system;
- an optimized benchmark;
- a replacement for existing repair-family evidence;
- a hidden alpha formula;
- a production signal.

## 8. Context Specification

### Economic Context

Economic Context is the primary comparator layer. It describes historically valid economic comparability among securities or economic companies. It may eventually include sector, industry, company-security relationships, listing identity, exchange history, ticker lineage, size, security type, and other comparability information only if future authority and identity gates accept those roles.

Scientific purpose:

- define the relevant comparison setting;
- prevent unrelated securities from being treated as peers;
- distinguish common economic recovery from target-specific repair;
- preserve the WS3 rule that economic context is a PIT comparison structure, not metadata decoration.

### Market Context

Market Context is the control layer that prevents broad market, stress, participation, volatility, liquidity, or transition effects from being mislabeled as peer-common repair.

Scientific purpose:

- keep common market recovery distinct from economic-peer recovery;
- preserve continuity with existing OHLCV-derived evidence;
- prevent the comparator from absorbing the meaning of existing repair, volatility, participation, persistence, or transition families.

### Deferred Macroeconomic Context

Macroeconomic Context remains deferred for the first module. Interest-rate, inflation, monetary, credit, business-cycle, or macro-stress context may become future Contextual Information only after separate authority, known-date, scope, and contamination review.

Scientific purpose when deferred:

- acknowledge that macro context may later explain common repair;
- prevent premature expansion of the first module;
- avoid introducing unavailable or source-specific macro timing assumptions.

No implementation is defined.

## 9. Information Flow

Conceptual information flow:

Alpha Observation: existing post-stress own-security repair

-> Contextual Observation: historically valid economic comparator repair and market context

-> Interpretation: distinguish common recovery from security-specific repair where evidence permits

-> Common-versus-idiosyncratic decomposition: classify the meaning of observed repair as common, target-specific, mixed, or unresolved

-> Future hypothesis evaluation: later formula, contamination, falsification, and validation work may ask whether the interpretation has predictive value

Governance Information surrounds every step: source authority, identity, lineage, PIT semantics, reproducibility, retention, auditability, and fail-closed rules determine whether any observation may be used beyond diagnostic reasoning.

## 10. Measurement Assumptions

Future formulas must preserve these assumptions:

- Source independence: the measurement meaning must not depend on any vendor, platform, source field, schema, programming language, or architecture.
- PIT consistency: target, comparator, identity, context, and source-known relationships must remain historically valid.
- Scientific reproducibility: observations must be preservable, auditable, and reconstructable under future accepted evidence.
- Bounded scope: the module measures repair decomposition only.
- No hidden contamination: current-state metadata, future peer membership, survivor-only sets, overwritten history, unresolved identity, or ungoverned source fallbacks must not enter the observation silently.
- No post hoc interpretation: decomposition meaning must be declared before empirical evidence is reviewed.
- Role separation: Alpha Information, Contextual Information, Governance Information, and interpretive outcomes must remain distinct.
- Evidence maturity separation: a measurement concept is not a validated signal.
- Failure safety: unresolved authority, identity, context, timing, coverage, or reproducibility must force diagnostic-only or fail-closed treatment in later lifecycle work.

## 12. Measurement Quality Criteria

A scientifically acceptable future measurement must be:

| Criterion | Requirement |
|---|---|
| Clear | The observation must state what scientific phenomenon is being captured. |
| Source-independent | The meaning must survive changes in source, schema, and implementation. |
| PIT-safe | The observation must not depend on future-known identity, context, classification, or peer membership. |
| Role-explicit | Alpha, context, governance, and interpretation roles must not blur. |
| Reproducible | Evidence needed to support the observation must be preservable or reconstructable. |
| Interpretable | The observation must support common-versus-idiosyncratic meaning, not opaque scoring. |
| Bounded | The observation must not absorb stabilization, asymmetry, VoV, liquidity, rank, transition, macro, event, or ML claims. |
| Contamination-aware | Known WS5 contamination paths must be visible at the measurement level. |
| Falsifiable | Future evidence must be able to show that the comparator adds no useful interpretation. |
| Compatible with negative evidence | Null, redundant, or contaminated outcomes must be preservable without relabeling the module. |

No quantitative thresholds are defined.
